## ncv_cylinder_buttons：气缸「动作」列改为「伸出 / 缩回」两个按钮

- **需求**：气缸（Cylinder）Tab 的「动作」列需要 2 个按钮：伸出、缩回（截图确认）。
- **`Views/MotionControlView.xaml`（plain，直接编辑）**：
  - 新增命名空间 `xmlns:helpers="clr-namespace:NoCodeVision.Helpers"`。
  - 气缸 `ListView` 的 `<GridViewColumn Header="动作" DisplayMemberBinding="{Binding Action}" Width="80">` 改为 `CellTemplate`，内含两个按钮：`伸出`（AppleBtn）与 `缩回`（AppleBtnSecondary），分别绑定 `Command="{x:Static helpers:CylinderCommandBridge.ExtendCmd/RetractCmd}" CommandParameter="{Binding}"`。
- **`Helpers/CylinderCommandBridge.cs`（NEW，plain）**：绕过加密 VM 的反射桥。
  - 两个根命令 `ExtendCmd` / `RetractCmd`（均 `RelayCommand`）。`Extend` 把 `row.Status="伸出"`、`row.Action="缩回"`；`Retract` 反之。
  - **关键坑**：`MotionRow.Status`/`Action` 在加密文件 `VisionMotionViewModels.cs` 里是**纯自动属性（无 INPC）**，直接赋值不会刷新 ListView。桥在赋值后用反射调用 `ViewModelBase.OnPropertyChanged(row, name)`（非 public，需 `BindingFlags.Instance|NonPublic`）强制刷新。
- **为什么走桥而不改 VM**：`VisionMotionViewModels.cs` 前 3 字节 `88 7d 1c` 是加密标记，其后是**加密二进制**（Grep 能回显明文，但 `raw[3:].decode('utf-8')` 抛 `UnicodeDecodeError: byte 0x99`），**无法 Python 字节编辑**。故凡是动气缸/运动行的逻辑，一律加新 plain `.cs` + 改 plain `.xaml`，不要碰这个加密文件。
- **验证**：`dotnet build -c Debug -p:BaseIntermediateOutputPath='obj6\' -p:OutputPath='bin6\'`（csproj 临时加 `obj\**;bin\**` 排除避沙箱锁）→ **0 错误**（仅 LuaDebugHost nullability 警告）。已**还原** csproj 为交付形态 `$(DefaultItemExcludes);LuaHostTest\**`（并移除临时 bin6/obj6 排除）。
- **当前状态**：气缸动作列按钮已实现并可编译；真实硬件伸出/缩回走硬件 API，本桥仅做 UI 状态切换与列表刷新（用户未要求接真机，故先不接 HardwareManager）。后续若要点按钮驱动真机，需在桥里调 `HardwareManager.Instance.Motion` 对应气缸 IO。

- **`ViewModels/ViewModels.cs` 的 `VariablesViewModel`（plain 但 CRLF 文本，Read 误判二进制 → 用 Python 读写）**：

## ncv_variables_remark_selection：变量表加「备注」列 + 修复选中行白字看不见

- **需求（用户）**：变量表再加一列「备注」（可编辑）；并修复「行点击后字体变白色、看不清」的问题，改成苹果风选中样式。
- **`ViewModels/ViewModels.cs` 的 `VarItem`**：新增 `public string Remark { get; set; } = "";`（CRLF 安全 Python 改写）。`FilterRow` 搜索条件追加 `|| (v.Remark != null && v.Remark.Contains(_searchText, OrdinalIgnoreCase))`，搜索框 tooltip 改「按名称、值或备注搜索」。
- **`Views/VariablesView.xaml`**：
  - 新增第三列 `备注`（Width="2*"）`DataGridTextColumn`，绑定 `Remark`，`UpdateSourceTrigger=PropertyChanged`，含 `ElementStyle`/`EditingElementStyle`（Padding 12,8、去边框），与名称/值列一致可编辑。
  - **修复选中白字**：根因是 `DataGridCell` 默认模板在 `IsSelected` 时用 `SystemColors.HighlightTextBrushKey`（白字）覆盖前景，而 `CellStyle` 静态 `Foreground` setter 优先级低于模板触发器，导致选中行文字变白、在浅底上看不见。
  - **修法（不改模板）**：在 `DataGrid.Resources` 内覆盖 4 个系统画刷为苹果风——`HighlightBrushKey`/`InactiveSelectionHighlightBrushKey` → `AccentSoftBrush` 浅色强调底（用 `Color="{Binding Source={StaticResource AccentSoftBrush}, Path=Color}"` 取色，避免写死 hex）；`HighlightTextBrushKey`/`InactiveSelectionHighlightTextBrushKey` → `TextPrimaryBrush` 深色字。需新增命名空间 `xmlns:sw="clr-namespace:System.Windows;assembly=PresentationFramework"` 以引用 `sw:SystemColors.*`。
  - 同时给 `CellStyle` 显式设 `Foreground=TextPrimaryBrush` 兜底非选中态深色字。
- **验证**：`dotnet build -c Debug -p:BaseIntermediateOutputPath='obj8\' -p:OutputPath='bin8\'`（csproj 临时加 `obj\**;bin\**`）→ **0 错误**（仅 LuaDebugHost 既有警告）。已还原 csproj 为 `$(DefaultItemExcludes);LuaHostTest\**`。
- **坑（沙箱锁）**：`obj6`/`obj7` 的输出 DLL 被 EDR/进程占用，`dotnet build` 到这两目录报 `CS2012 Access denied`，故每次换全新输出目录（`obj8\`/`bin8\`）绕过。
- **当前状态**：备注列 + 苹果风选中均已实现可编译；选中行现为浅蓝底 + 深色字，不再白字看不见。待用户 VS rebuild + F5 实跑确认视觉效果。
