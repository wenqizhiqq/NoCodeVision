## 修复：匹配框显示位置错位 + 模板预览高度 1.5× + 开始匹配显示耗时（ncv_b16）
- **匹配框位置错位的双重根因**：
  1. 时序问题：`RoiImageView.OnSourceChanged`/`OnOverlaysChanged` 在图像元素尚未完成布局时即 `RenderAll()`，此时 `Img.ActualWidth/Height == 0`，`GetImageRect` 退回 `scale=1, offX=0`，叠加框按原始像素坐标绘制而错位。修复：构造器订阅 `Img.SizeChanged` + `Img.LayoutUpdated` 重绘；两回调改用 `Dispatcher.BeginInvoke(DispatcherPriority.Render, ...)` 延后到布局完成后再画；`GetImageRect` 在 `Img` 尺寸为 0 时兜底用控件自身 `ActualWidth/Height`。
  2. **尺寸被二次缩放**：`StartMatchCmd` 原写 `W = r.TemplateWidth * r.Scale`，但原生 `RotatedTemplateMatcher.Match` 返回的 `TemplateWidth/Height` 已是 `native * mapFactor`（`Scale == mapFactor`），再乘一次会把框放大 `mapFactor²` 倍。改为 `W = r.TemplateWidth; H = r.TemplateHeight`（与 `VisionMotionViewModels` 已验证路径一致）。
- **角度符号统一**：`StartMatchCmd` 叠加框原 `AngleDeg = r.Angle`，与已验证路径相反；改为 `AngleDeg = -r.Angle`。
- **模板预览高度 1.5×**：`Views/FlowView.xaml` 模板预览区 `Border`/`Image` 的 `Height` 由 `100` 改为 `150`（宽保持 `140`，`Stretch=Uniform` 保持比例）。
- **开始匹配显示耗时**：`StartMatchCmd` 用 `Stopwatch` 包裹 `Match(...)`，写入 `_selectedStep.CostMs`；叠加框标签追加 `score {x} {CostMs}ms`，`ActualValue` 与 `StatusText` 均带 `耗时{ms}ms`。
- **验证**：`tar` 复制到 `D:\temp\ncv_b16` 后 `dotnet build -c Release` 通过，**0 警告 0 错误**；输出根目录含 `GrayModelNative.dll` + `opencv_world480.dll` + `OpenCvSharpExtern.dll`。

## 修复：叠加框/ROI 整体偏移（靠左/偏向一侧）（ncv_b19）
- **根因**：`GetImageRect` 之前用 `Img.ActualWidth/Height` 计算黑边偏移 `offX/offY`，并默认 `Img` 元素左上角就是控件左上角（origin=0,0）。若 `Img` 因布局被约束成「内容尺寸」而非撑满控件（典型：容器比图像更宽/更高时 `Stretch=Uniform` 元素被居中），其实体相对控件有偏移，导致 `offX` 少算该偏移，所有叠加框与 ROI 整体偏向一侧（实测整体靠左）。
- **修复**：`GetImageRect` 用 `Img.TranslatePoint(new Point(0,0), this)` 取得 `Img` 元素在 `RoiImageView` 控件坐标系中的真实左上角 `elemX/elemY`，`offX = elemX + (ew-dw)/2`、`offY = elemY + (eh-dh)/2`（布局未完成时回退控件自身尺寸，elemX/Y 取 0）。
- **同源修复**：鼠标拖拽 `OnMouseDown/OnMouseMove` 由 `e.GetPosition(Img)` 改为 `e.GetPosition(this)`（控件坐标），使 ROI 绘制与叠加框渲染使用同一 origin，避免拖拽 ROI 与显示不一致。
- **验证**：`tar` 复制到 `D:\temp\ncv_b19` 后 `dotnet build -c Release` 通过，**0 警告 0 错误**；输出根目录含三个原生 DLL。
