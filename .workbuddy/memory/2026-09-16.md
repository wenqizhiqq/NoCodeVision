## 流程后台线程运行 + UI 定时刷新（已修复卡顿 · 0 错误验证）



用户要求：运行的流程不能卡顿界面，需要在 thread 跑，由定时器刷新界面。



### 卡顿根因

`RunAllFlowsLoopAsync`/`RunSingleFlowStepsAsync` 是 async 但内部 `RunStep`（视觉计算）是同步重活；async 在 UI 线程发起、`await Task.Delay` 后延续回到 UI SynchronizationContext → 重活在 UI 线程执行 → 界面冻结。



### 改动

- **ViewModels/OperatorRunViewModel.cs**

  - 新增 `DispatcherTimer _uiTimer`（100ms 节拍）+ `FlowProductResult? _pendingResult`（后台写、UI 消费）

  - `StartRealProduction`：主流程循环改为 `Task.Run(async () => await FlowViewModel.Instance.RunAllFlowsLoopAsync(_flowCts.Token))` 真正后台线程

  - `OnFlowProductInspected`：只把结果暂存到 `_pendingResult` + 下发 PLC，不再直接碰 UI

  - 新增 `OnUiTimerTick`：UI 线程按 100ms 把 `_pendingResult` 刷进 Total/Ok/Ng/各通道 LastImage 等指标（先取后清，天然节流）

  - `StartRun` 启动 `_uiTimer`；`Stop`/`EStop`/`Reset` 停止它

  - `Reset` 的复位流程也用 `Task.Run` 后台跑

- **ViewModels/ViewModels.cs**

  - `FlowViewModel.StartLoopAsync`（流程页「运行全部流程」）：`await Task.Run(() => fvm.RunAllFlowsLoopAsync(...))`

  - `RunAllAsync`（流程页单个运行）：`await Task.Run(() => RunSingleFlowStepsAsync(...))`



### 验证

- E: 沙箱（E:\ncb_thread）`dotnet build -c Debug`：**0 错误 / 60 警告**。

## 修复：工具箱下拉框 BodyTextBrush 资源不存在导致运行时崩溃
用户反馈（VS 异常截图）：FlowView 运行即崩，StaticResourceExtension 行281 找不到「BodyTextBrush」。
根因：BodyTextBrush 是 SMotorseWpf/BasicClassProject 的画刷键，NoCodeVision 里没有；本项目对应键为 TextSecondaryBrush。
改动：Views/FlowView.xaml 工具箱行内「分类/工具」两个 TextBlock 的 Foreground 改为 {StaticResource TextSecondaryBrush}。
验证：E:\ncb_toolbox_n 沙箱构建 **0 错误**。
教训：跨项目复用 XAML 片段时，画刷键必须先用 Grep 确认本项目资源字典里存在，StaticResource 缺键是运行时崩溃不是编译错误。
